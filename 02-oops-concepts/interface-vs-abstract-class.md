| Feature          | Abstract Class      | Interface                                       |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Basic Meaning**                | An abstract class is a normal class that is marked as `abstract`. It can contain both implemented methods (with code) and unimplemented methods (without code). It is used when we want to provide some common functionality along with some rules. | An interface is a completely abstract structure that defines only what methods a class must have. It is mainly used to provide a contract that classes must follow, without caring about how the work is done. |
| **Purpose**                      | The main purpose is to share common behavior among related classes while still forcing them to implement some specific methods. It helps in code reuse and structure.                                                                               | The main purpose is to define a standard rule so that different unrelated classes can follow the same pattern. It helps in building flexible and loosely coupled systems.                                      |
| **Keyword Used**                 | It is created using the `abstract class` keyword. This tells Java that this class cannot be instantiated directly.                                                                                                                                  | It is created using the `interface` keyword, which tells Java that this is only a blueprint, not a real class.                                                                                                 |
| **Method Implementation**        | It can have both abstract methods (without body) and concrete methods (with body). This means it supports partial implementation.                                                                                                                   | Traditionally, interfaces contain only abstract methods. From Java 8 onward, they can also have `default` and `static` methods, but most methods are still abstract.                                           |
| **Method Body**                  | Abstract classes allow method bodies. This means you can write real logic inside methods and reuse it in child classes.                                                                                                                             | Interfaces do not usually allow method bodies (except default/static). Most methods only declare the signature without logic.                                                                                  |
| **Variables**                    | Variables in abstract classes behave like normal class variables. They can be private, protected, non-final, and changeable.                                                                                                                        | Variables in interfaces are automatically `public`, `static`, and `final`. This means they are constants and cannot be changed.                                                                                |
| **Constructors**                 | Abstract classes can have constructors. These are used to initialize variables when a child class object is created.                                                                                                                                | Interfaces cannot have constructors because they are not part of object creation. They do not represent real objects.                                                                                          |
| **Access Modifiers for Methods** | Methods in abstract classes can use any access modifier: private, protected, default, or public.                                                                                                                                                    | Methods in interfaces are public by default. You cannot make them private (except helper methods in Java 9+).                                                                                                  |
| **Inheritance Type**             | A class can extend only one abstract class. Java does not allow multiple inheritance using classes.                                                                                                                                                 | A class can implement multiple interfaces. This is how Java supports multiple inheritance.                                                                                                                     |
| **Multiple Inheritance Support** | Multiple inheritance is not supported because extending more than one class can cause ambiguity.                                                                                                                                                    | Multiple inheritance is supported because interfaces only define rules and do not cause confusion in implementation.                                                                                           |
| **Relationship Type**            | Abstract classes represent an "IS-A" relationship. The child class is a type of parent class.                                                                                                                                                       | Interfaces represent a "CAN-DO" relationship. The class gains abilities defined by the interface.                                                                                                              |
| **Level of Abstraction**         | Abstract classes provide partial abstraction. Some details are hidden, and some are visible.                                                                                                                                                        | Interfaces provide full abstraction. They mainly hide implementation details and show only behavior.                                                                                                           |
| **Code Reusability**             | Abstract classes are good for code reuse because they can store common logic in implemented methods.                                                                                                                                                | Interfaces do not focus on code reuse. They focus more on design rules and structure.                                                                                                                          |
| **Flexibility**                  | Abstract classes are less flexible because a class can extend only one class.                                                                                                                                                                       | Interfaces are more flexible because a class can implement many interfaces.                                                                                                                                    |
| **Performance**                  | Abstract classes are slightly faster because method calls are directly linked to class hierarchy.                                                                                                                                                   | Interfaces are slightly slower because Java has to resolve method calls at runtime, but the difference is negligible.                                                                                          |
| **Object Creation**              | You cannot create an object of an abstract class directly. You must create an object of its child class.                                                                                                                                            | You cannot create an object of an interface. You must use a class that implements it.                                                                                                                          |
| **Design Usage**                 | Abstract classes are used when you are designing base classes for closely related objects.                                                                                                                                                          | Interfaces are used when you are designing frameworks, APIs, and large systems.                                                                                                                                |
| **Real-World Analogy**           | Like a partially built house: some rooms are ready, others must be completed by the owner.                                                                                                                                                          | Like a rulebook: it only tells what rules to follow, not how to play.                                                                                                                                          |
| **Best Use Case**                | Best when classes share common data and behavior and belong to the same family.                                                                                                                                                                     | Best when different classes need to follow the same behavior but are not closely related.                                                                                                                      |
